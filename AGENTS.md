## Quick Reference

## Development Workflow

### 1. Before Making Changes

```bash
# Ensure you're on a feature branch
git checkout -b feature/my-feature-name

# Pull latest changes
git pull origin main

# Run pre-commit hooks (they run automatically on commit)
pre-commit install
```

### 2. During Development

```bash
# Format your code
black . && isort .

# Check types
mypy .

# Run tests affected by your changes
pytest tests/ -v

# Check coverage
pytest tests/ --cov --cov-report=term-missing
```

### 3. Before Committing

```bash
# Run all pre-commit hooks
pre-commit run --all-files

# Full test suite
pytest tests/ --cov --cov-report=html

# Verify coverage threshold (>=95%)
coverage report --fail-under=95
```

### 4. Commit Message Format

Use **Conventional Commits** format:

```
<type>(<scope>): <subject>

<body>

<footer>
```

**Types**: `feat`, `fix`, `docs`, `style`, `refactor`, `perf`, `test`, `chore`, `ci`

**Examples**:

```
feat(trading): add support for options Greeks calculation

Implement QuantLib integration to calculate delta, gamma, theta, vega,
and rho for options positions.

Closes #123
```

```
fix(database): resolve connection pool exhaustion in ClickHouse

Increase max_connections from 100 to 500 to handle concurrent queries
during high-load periods. Add connection pool monitoring.

Fixes #456
```

## Testing Guidelines

### Test Organization

- **Unit tests** (`tests/unit/`): Test individual functions/classes in isolation
- **Integration tests** (`tests/integration/`): Test interactions between components
- **End-to-end tests** (`tests/e2e/`): Test complete workflows
- **Performance tests** (`tests/performance/`): Benchmark critical paths

### Test Coverage Requirements

- **Minimum**: 95% coverage threshold
- **New code**: Must achieve >95% coverage before merging
- **Critical paths**: Trading engine, risk manager, order management require 100% coverage

### Running Tests

```bash
# All tests
pytest tests/ -v

# Specific test file
pytest tests/unit/test_quant.py -v

# Specific test function
pytest tests/unit/test_quant.py::TestQuantLib::test_fibonacci_retracement -v

# With coverage
pytest tests/ --cov=libs --cov-report=html

# Run only failed tests from last run
pytest tests/ --lf

# Run tests matching a pattern
pytest tests/ -k "fibonacci or gann" -v
```

## Database Management

### Available Databases

1. **PostgreSQL 17 + pgvector**: Transactions, fundamentals, vector embeddings
   - Connection: `postgres://user:pass@localhost:5432/trading_db`
   
2. **ClickHouse 24.8**: Time-series data, market data
   - Connection: `clickhouse://localhost:8123/trading_analytics`
   
3. **Neo4j 5.25**: Knowledge graph, agent workflows
   - Connection: `bolt://localhost:7687`
   
4. **Redis 7.4**: Caching, sessions

## Common Pitfalls & Solutions

### Issue: Poetry lock conflicts

**Problem**:
```
poetry lock fails with dependency resolution errors
```

**Solution**:
```bash
poetry cache clear --all pypi
poetry lock --no-update
```

### Issue: Tests fail with import errors

**Problem**:
```
ModuleNotFoundError: No module named 'libs.common'
```

**Solution**:
```bash
poetry install
# or ensure you're in poetry shell
poetry shell
```

### Issue: Mypy type errors

**Problem**:
```
error: Missing return statement
error: Incompatible return value type
```

**Solution**:
- Add explicit return statements
- Ensure type hints match actual return types
- Use `Any` only when absolutely necessary

### Issue: Pre-commit hooks fail

**Problem**:
```
pre-commit failed during git commit
```

**Solution**:
```bash
# Run hooks manually to see error details
pre-commit run --all-files

# Skip hooks (not recommended for final commits)
git commit --no-verify -m "message"
```

## Performance Guidelines

### Critical Performance Targets

- **Order Execution Latency (p95)**: <100μs
- **API Response Time (p95)**: <200ms
- **Database Query (OLTP, p95)**: <10ms
- **WebSocket Latency**: <100ms

### Optimization Techniques

1. **Use async/await** for I/O-bound operations
2. **Batch database writes** where possible
3. **Leverage Redis** for caching frequent queries
4. **Use ClickHouse** for time-series analytics
5. **Profile** with Python's `cProfile` or `py-spy` for bottlenecks

## Security Considerations

- **Never commit secrets**: API keys, passwords, tokens
- **All secrets in `.env`** (gitignored)
- **Use JWT tokens** with 15-minute expiry
- **Implement RBAC** for API endpoints
- **Validate input** at all entry points
- **Run security scans**: `bandit -r services/`
